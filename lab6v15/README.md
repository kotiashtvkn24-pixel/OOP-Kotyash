## Опис ієрархії

- **Clothing** (базовий): поля `_material`, `_size`, властивості `Material`, `Size`, конструктор, `virtual void Wear()`, метод `GetClothingType()` (не віртуальний).
- **Shirt** (похідний): властивість `SleeveLength`, конструктор з `base(...)`, `override Wear()`, власний метод `ButtonUp()`, `new GetClothingType()`.

Метод `Wear()` (override) викликається за реальним типом об'єкта, тому через посилання `Clothing` виконується версія з `Shirt`. Метод `GetClothingType()` (new) викликається за типом посилання: через `Shirt` це "Сорочка", через `Clothing` це "Одяг".

## Відповіді на контрольні запитання

**1. Поясніть принцип наслідування в ООП. Наведіть приклад з реального світу.**
Наслідування дозволяє створити новий клас на основі наявного, який отримує його поля й методи та може додати свої. Приклад: "Транспорт" це базовий клас, а "Автомобіль" і "Велосипед" його похідні: вони мають спільні риси транспорту й свої особливості. У нашій роботі Shirt і Pants успішно наслідують Clothing.

**2. Для чого використовується ключове слово base?**
Для доступу до членів базового класу. Найчастіше для виклику конструктора базового класу: `Shirt(...) : base(material, size)`. Також можна викликати метод базового класу: `base.Wear()`.

**3. У чому різниця між virtual та override? Як вони забезпечують поліморфізм?**
`virtual` у базовому класі дозволяє змінювати метод у похідних. `override` у похідному класі надає нову реалізацію цього методу. Під час виклику через посилання на базовий клас виконується версія реального об'єкта, а це і є поліморфізм.

**4. Коли варто використовувати new та які наслідки?**
`new` приховує успадкований не віртуальний член, коли потрібен метод з тим самим іменем, але без поліморфізму. Наслідок: який метод викликається, залежить від типу посилання, а не від типу об'єкта. Це може заплутувати, тому використовувати його слід рідко.
