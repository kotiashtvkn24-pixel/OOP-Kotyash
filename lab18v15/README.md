# Лабораторна робота №18

## Тема
Власні винятки та патерн Result.

## Варіант
15 — Обробка повідомлень.

## Мета роботи
Навчитися створювати власні типи винятків та використовувати патерн Result для контрольованої обробки помилок.

## Хід роботи

### 1. Власний виняток MessageProcessingException

Створено клас `MessageProcessingException`, який успадковується від `Exception`.

Властивості:
- `MessageId` — ідентифікатор повідомлення.
- `Details` — опис помилки.

Виняток виникає, якщо повідомлення пошкоджене або має неправильний формат.

### 2. Узагальнений клас Result<T>

Створено клас `Result<T>`, який містить:
- `IsSuccess` — статус виконання операції.
- `Value` — результат операції.
- `Error` — опис помилки.

Реалізовано методи:
- `Success(T value)` — повертає успішний результат.
- `Failure(string error)` — повертає помилку.
- `Failure(Exception ex)` — створює помилковий результат на основі винятку.

### 3. Клас MessageProcessor

Реалізовано два основні методи:

- `ProcessMessage(string message)` — обробляє повідомлення та викидає `MessageProcessingException`, якщо повідомлення пошкоджене.
- `SendMessage(string message)` — повертає `Result<bool>` та перевіряє правильність адреси одержувача й наявність тексту повідомлення.

### 4. Результат виконання програми

```text
=== Обробка повідомлень ===
Повідомлення MSG001 успішно оброблено.
Текст: Привіт! Це тестове повідомлення.
Власний виняток:
ID повідомлення: MSG002
Помилка: Повідомлення пошкоджене або має неправильний формат.

=== Відправлення повідомлень ===
Повідомлення успішно відправлено.
Помилка: Некоректна адреса одержувача.
```

### 5. Висновок

Під час лабораторної роботи було створено власний виняток `MessageProcessingException` та узагальнений клас `Result<T>`. Було реалізовано обробку повідомлень і перевірку адреси одержувача. Власні винятки доцільно використовувати для серйозних помилок обробки повідомлень, а `Result<T>` — для очікуваних ситуацій, наприклад неправильної адреси одержувача.

## Контрольні запитання

**1. Навіщо створювати власні типи винятків? Які переваги це дає?**

Власні винятки дозволяють описувати специфічні помилки програми. Вони роблять обробку помилок зрозумілішою та дають змогу зберігати додаткову інформацію про помилку.

**2. Які стандартні конструктори рекомендується реалізовувати для власних винятків?**

Рекомендується реалізовувати три конструктори:
- Без параметрів.
- З параметром `string message`.
- З параметрами `string message` та `Exception innerException`.

**3. Поясніть патерн Result. У яких випадках його використання є більш доцільним, ніж викидання винятків?**

Патерн Result повертає об'єкт, який містить результат операції або інформацію про помилку. Його доцільно використовувати для очікуваних помилок, наприклад неправильних вхідних даних.

**4. Які сценарії краще обробляти через винятки, а які через патерн Result?**

Винятки краще використовувати для неочікуваних або серйозних помилок. Result краще підходить для звичайних ситуацій, коли операція може не виконатися через неправильні дані або невиконані умови.
