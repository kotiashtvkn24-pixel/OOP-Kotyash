
# Лабораторна робота №17

**Тема:** Обробка IO/мережевих помилок та патерн Retry

**Варіант:** 15

**Виконав:** Котяш Тарас

## Мета роботи

Навчитися обробляти типові помилки вводу/виводу та мережеві помилки за допомогою try-catch-finally, а також реалізувати патерн Retry для підвищення відмовостійкості застосунків.

## Опис програми

У програмі створено три класи:

- FileProcessor — імітує завантаження конфігурації з файлу.
- NetworkClient — імітує завантаження конфігурації з мережі.
- RetryHelper — реалізує повторні спроби виконання операцій з експоненційною затримкою.

## Виконання завдань

1. FileProcessor — перші 2 спроби завершуються IOException, третя успішна.
2. NetworkClient — перші 3 спроби завершуються HttpRequestException, четверта успішна.
3. RetryHelper — реалізує ExecuteWithRetry<T> з повторними спробами.
4. Експоненційна затримка — час очікування збільшується вдвічі після кожної невдалої спроби.
5. shouldRetry — дозволяє повторювати операції лише для IOException та HttpRequestException.
6. Додатково перевірено обробку UnauthorizedAccessException без повторних спроб.

## Висновок

Під час лабораторної роботи було реалізовано обробку файлових і мережевих помилок за допомогою механізму винятків. Створено RetryHelper з експоненційною затримкою, яка збільшує час очікування після кожної невдалої спроби. Також використано shouldRetry для вибіркового повторення операцій.

## Контрольні запитання

### 1. Які типи винятків найчастіше виникають при роботі з файлами та мережею?

При роботі з файлами виникають IOException, FileNotFoundException та DirectoryNotFoundException. При роботі з мережею — HttpRequestException та SocketException.

### 2. Поясніть принцип роботи патерну Retry. Коли його доцільно використовувати?

Retry — це повторне виконання операції після тимчасової помилки. Його використовують при нестабільному мережевому з'єднанні або тимчасових помилках доступу до файлів.

### 3. Як реалізувати експоненційну затримку між повторними спробами?

Час очікування збільшується вдвічі після кожної невдалої спроби. Формула: initialDelay * 2^retryAttempt.

### 4. Для чого потрібен делегат shouldRetry у допоміжному класі RetryHelper?

shouldRetry визначає, для яких винятків потрібно виконувати повторну спробу, а для яких операцію потрібно припинити.
